# APEX Ω∞ — سیستم کاور هنرمندان آهنگ‌بان

زیرساخت قابل‌تکرار برای پذیرش مرجع، نهایی‌سازی پرتره، مدیریت نشان تأیید، نسخه‌بندی و کنترل کیفیت کاورهای `1080×1080` آهنگ‌بان.

> **محدودیت صریح:** این مخزن مدل تصویرساز داخلی ندارد. دستور `intake` پرتره یا حفظ هویت را جعل نمی‌کند؛ مرجع، پرامپت ثابت و پروژه را آماده می‌کند. در حالت کلی، پرتره باید در یک مدل بیرونی با قابلیت **ویرایش مبتنی بر تصویر مرجع** ساخته و سپس با `finalize` نهایی شود. اگر مرجع از نظر هویت، نور و پس‌زمینه مناسب باشد، ویرایش غیرمولّدِ مستند (مانند برش و تغییر اندازه) نیز می‌تواند master ورودی باشد؛ این مسیر نباید تولید AI یا تغییر نور/پس‌زمینه تلقی شود. پذیرش نهایی همچنین به بازبینی بصری واقعی نیاز دارد.

## شروع سریع

```bash
python3 -m venv .venv
. .venv/bin/activate             # در Windows: .venv\Scripts\activate
python -m pip install -e '.[dev]'
```

برای هر هنرمند تازه فقط سه ورودی اجباری لازم است:

```bash
ahangban-artist intake \
  --reference "/path/to/reference.png" \
  --name-fa "نام فارسی هنرمند" \
  --name-en "Artist Latin Name"
```

وضعیت پیش‌فرض **تأییدنشده** است. فقط با دادهٔ صریح کاربر از `--verified` استفاده کنید؛ برای ثبت صریح حالت تأییدنشده نیز `--unverified` موجود است.

این دستور:

- نام‌ها را بدون تغییر معنایی در JSON نگه می‌دارد و از نام لاتین slug می‌سازد؛
- مرجع را با همان بایت‌ها و پسوند واقعی در `source/` کپی می‌کند؛
- وجود پوشه یا نام‌های احتمالاً تکراری را بررسی می‌کند؛
- پرامپت، لایه‌های SVG نشان، فراداده و تاریخچه را آماده می‌کند؛
- هیچ پرتره‌ای تولید نمی‌کند و هیچ Commit یا Push‌ای انجام نمی‌دهد.

## تولید و نهایی‌سازی

1. در حالت نیاز به تولید، مرجع و پرامپت ثابت [`brand-kit/prompts/artist-portrait-fa.txt`](brand-kit/prompts/artist-portrait-fa.txt) را به مدل بیرونیِ دارای ویرایش تصویرمرجع بدهید. نام هنرمند، متن، لوگو و نشان را از مدل تصویرساز نخواهید. اگر خود مرجع از نظر نور و پس‌زمینه مناسب است، می‌توانید فقط برش غیرمولّد و مستند انجام دهید و روش واقعی را در `--generator` ثبت کنید.
2. پرترهٔ بیرونی یا برش غیرمولّد مرجع را بدون لوگو و نشان ذخیره کنید.
3. خروجی برند را بسازید:

```bash
ahangban-artist finalize \
  --artist artist-latin-name \
  --master "/path/to/edited-master.png" \
  --generator "نام واقعی مدل/ابزار، در صورت اطلاع"
```

خروجی نهایی و master هر دو `1080×1080` و PNG با پروفایل sRGB هستند. نسبت تصویر کشیده نمی‌شود؛ نسخهٔ غیرمربع با روش contain روی زمینهٔ `#111111` قرار می‌گیرد. لوگوی رسمی شفاف و نشانِ مطابق وضعیت فقط روی خروجی نهایی ترکیب می‌شوند.

## تغییر نسخه و وضعیت تأیید

بازنویسی پیش‌فرض ممنوع است. برای جایگزینی همراه با حفظ نسخهٔ قبلی:

```bash
ahangban-artist finalize \
  --artist artist-latin-name \
  --master "/path/to/new-master.png" \
  --on-existing archive \
  --change "شرح واقعی اصلاح نسخه"
```

تغییر وضعیت، پرترهٔ اصلی را دوباره تولید یا تغییر نمی‌کند:

```bash
ahangban-artist set-verification --artist artist-latin-name --verified --reason "تأیید صریح دادهٔ پروژه"
ahangban-artist set-verification --artist artist-latin-name --unverified --reason "حذف صریح وضعیت تأیید"
```

نسخه‌های قبلی در `history/revisions/vNNN/` بایگانی می‌شوند؛ مرجع اصلی دست‌نخورده می‌ماند.

## QC و پذیرش بصری

```bash
ahangban-artist qc --artist artist-latin-name
```

QC فنی، سلامت PNG، ابعاد، حالت رنگ و ICC، هش مرجع و دارایی‌ها، تطابق وضعیت/نشان، مسیرهای فراداده و بازتولید قطعی خروجی و پیش‌نمایش دایره‌ای را بررسی می‌کند. این ابزار تشخیص چهره انجام نمی‌دهد و هویت یا ایمنی قاب را خودکار تأیید نمی‌کند.

فقط پس از مشاهدهٔ مرجع، master، خروجی نهایی، اندازهٔ کوچک و پیش‌نمایش دایره‌ای، بازبین می‌تواند نتیجه را ثبت کند:

```bash
ahangban-artist approve \
  --artist artist-latin-name \
  --reviewer "نام بازبین" \
  --notes "شرح بازبینی واقعی"
```

تا پیش از این مرحله، وضعیت پذیرش `pending-visual-review` است. اجرای `approve` یک **ثبت اظهار بازبین** است، نه تست خودکار هویت.

## گزارش

```bash
ahangban-artist report --artist artist-latin-name
ahangban-artist report --artist artist-latin-name --json
```

گزارش شامل نام‌ها، وضعیت تأیید، مسیرها، مشخصات فنی، تغییرات، محدودیت‌ها و وضعیت QC است. بخش GitHub عمداً `not-attempted-by-cli` می‌ماند؛ فقط خروجی موفق واقعی `git`/`gh` باید به‌عنوان Commit یا Push گزارش شود.

## ساختار هر هنرمند

```text
brand-kit/artists/<artist-slug>/
├── source/reference-original.<actual-format>   # بایت‌های اصلی، بدون تغییر
├── portrait/
│   ├── artist-master.png                       # بدون لوگو و نشانِ افزوده‌شده توسط pipeline
│   ├── artist-1080x1080.png                    # خروجی نهایی با لوگوی رسمی و وضعیت جاری
│   └── artist-verified-preview.png             # یا artist-unverified-preview.png؛ برش دایره‌ای
├── badges/verified-blue.svg                    # لایهٔ تیک آبی
├── badges/verified-gold.svg                    # لایهٔ حلقهٔ طلایی محدود
├── metadata/artist.json
├── metadata/qc.json                            # پس از نهایی‌سازی/QC
└── history/CHANGELOG.md
```

فقط پیش‌نمایش وضعیت جاری ساخته می‌شود تا برای هنرمند تأییدنشده خروجی تأییدشدهٔ بی‌استفاده تولید نشود. رابط سایت باید وضعیت را از `artist.json` یا دادهٔ معتبر دیگر بخواند؛ پیکسل نشان مدرک احراز هویت نیست.

## آزمون و CI

```bash
python -m pytest
```

تست‌ها از fixture هندسی غیرانسانی در پوشهٔ موقت استفاده می‌کنند و هیچ هنرمند آزمایشی یا تصویر خروجی را در مخزن ثبت نمی‌کنند. آزمون فنی جای آزمون هویت یک هنرمند واقعی را نمی‌گیرد.

راهنمای کامل طراحی و عملیات در [`brand-kit/README-fa.md`](brand-kit/README-fa.md)، منشأ لوگوها در [`logo-ahangban/SOURCES.md`](logo-ahangban/SOURCES.md) و مرز دقیق آزمون‌های انجام‌شده در [`brand-kit/ACCEPTANCE-fa.md`](brand-kit/ACCEPTANCE-fa.md) ثبت شده است.
